Memory Go: connecting to the database

How a page reads and saves data, and how to add your own feature. Worked example: the progress table (xp and coins).

The picture Setup once Three rules Read from a page Save from a page Add your own feature Testing Common errors
In one sentence. Pages call api.get(...) / api.post(...). Our Express server checks who is asking, talks to Supabase, and sends JSON back. Pages never talk to Supabase directly for data.

Setup once, on your machine

  1. Get the env values from Ariq privately (not from git, not from the group chat). Two files, each has an .env.example next to it showing the names: 
    # memorygo/.env.local
VITE_SUPABASE_URL=
VITE_SUPABASE_PUBLISHABLE_KEY=

# server/.env
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
PORT=8000
CLIENT_ORIGIN=http://localhost:5173
  2. Install both halves: 
    cd IS216-Project/memorygo && pnpm install
cd IS216-Project/server   && pnpm install
  3. Run both, in two terminals: 
    cd IS216-Project/server   && pnpm dev     # API on http://127.0.0.1:8000
cd IS216-Project/memorygo && pnpm dev     # site on http://localhost:5173
  4. Sign up once at /signup so you have a user to test with. Every page except landing/login/signup is behind the login.
Never put SUPABASE_SERVICE_ROLE_KEY anywhere in memorygo/. It bypasses all database security. It lives only in server/.env.

Three rules

RuleWhy
Pages call api.get / api.post, never supabase.from(...).The server is where "who is asking" is verified and where game rules live. Calling Supabase from the browser skips both.
Every route starts with requireAuth and filters by req.user.id.The server's key can read anyone's rows. The filter is what keeps users in their own lane.
The browser says what happened, the server decides what it's worth.{ game: 'memory' }, not { xp: 5000 }. A player with DevTools can't award themselves anything.

Read data from a page

This is the lab's loadData pattern. Same shape, with the URL and token handled for you.

<!-- any page, e.g. menu.vue or profile.vue -->
<script setup>
import { ref, onMounted } from 'vue'
import { api } from '@/lib/api'

const progress = ref({ xp: 0, coins: 0 })   // placeholder until the server answers
const loadError = ref('')

async function loadProgress() {
    try {
        const { data } = await api.get('/progress')   // GET http://127.0.0.1:8000/api/progress
        progress.value = data
    } catch {
        loadError.value = "Couldn't load your progress."
    }
}

onMounted(loadProgress)   // once, when the page appears
</script>

<template>
    <p v-if="loadError" class="text-danger">{{ loadError }}</p>
    <p v-else>XP: {{ progress.xp }} · Coins: {{ progress.coins }}</p>
</template>
  • The ref starts with zeros so there's no flash of "undefined" before the reply.
  • onMounted runs once when the component is on screen. Right place to fetch.
  • try/catch handles a server that's down or a session that expired. Show a sentence, don't crash.
  • .data is the JSON body. axios wraps replies with status and headers you don't need here.

Save data from a page

Tell the server what happened. It works out the result and sends back the new state.

// e.g. at the end of memory.vue, when the player wins
import { api } from '@/lib/api'

async function onGameWon() {
    try {
        const { data } = await api.post('/progress/xp', { game: 'memory' })
        // data is { xp: 170, coins: 30 } — the new totals, decided by the server
        showReward(data)
    } catch {
        // show "couldn't save, try again"
    }
}

The second argument to api.post becomes req.body on the server. Send the minimum the server needs to apply its rule.

Add your own feature (e.g. collection)

Five steps. The worked example is progress; swap in your own names.

1. Create the table in Supabase

Table Editor → New table. Always include a user_id column:

ColumnTypeSettings
idint8primary (default, leave it)
created_attimestamptzdefault now() (default, leave it)
user_iduuidno default (clear the box), foreign key → auth.users.id, "Is Unique" if one row per user
your columns…e.g. item_id text, collected_at timestamptz

Leave "Enable Row Level Security" ticked.

2. Add one SELECT policy

Table → Policies → New policy → "For full customization". Command SELECT, USING expression:

auth.uid() = user_id

No INSERT/UPDATE/DELETE policies for users. The server does the writing.

3. Write server/routes/<feature>.js

Copy progress.js. The skeleton:

import { Router } from 'express'
import { requireAuth } from '../middleware/auth.js'
import { supabase } from '../supabase.js'

const router = Router()

// GET /api/collection  → all items this user has collected
router.get('/', requireAuth, async (req, res) => {
    const { data, error } = await supabase
        .from('collection')
        .select('item_id, collected_at')
        .eq('user_id', req.user.id)          // ALWAYS

    if (error) return res.status(500).json({ message: 'Could not load collection.' })
    res.json(data)
})

// POST /api/collection  body: { itemId }  → add one item
router.post('/', requireAuth, async (req, res) => {
    const { itemId } = req.body
    if (!itemId) return res.status(400).json({ message: 'Missing itemId.' })

    const { data, error } = await supabase
        .from('collection')
        .insert({ user_id: req.user.id, item_id: itemId })   // user_id from the token, never from the body
        .select()
        .single()

    if (error) return res.status(500).json({ message: 'Could not save item.' })
    res.status(201).json(data)
})

export default router

4. Mount it in server/server.js

import collectionRoutes from './routes/collection.js'
// ...next to the other app.use lines
app.use('/api/collection', collectionRoutes)

The prefix here plus the path inside the file is the full URL. router.post('/') in a file mounted at /api/collection is POST /api/collection.

5. Call it from your page

const { data } = await api.get('/collection')
await api.post('/collection', { itemId: 'merlion' })
Supabase query cheatsheet (inside a route): .select('a, b') read columns · .eq('col', v) filter · .maybeSingle() one row or null · .single() exactly one row · .insert({...}) · .update({...}).eq(...) · .upsert({...}, { onConflict: 'user_id' }) insert-or-update · .delete().eq(...) · .order('col', { ascending: false }). Every call returns { data, error }. Always check error.

Testing without a page

Both servers running, signed in on the site. Open the browser console on any page:

const { api } = await import('/src/lib/api.js')
;(await api.get('/progress')).data
;(await api.post('/progress/xp', { game: 'memory' })).data
;(await api.post('/progress/xp', { game: 'cheat' })).data     // 400 — server refuses unknown games

Line 1 loads the helper into the console. The leading ; on the others is a paste quirk, not something you write in files. A 4xx/5xx shows as a red error, which is axios throwing on purpose.

Server up at all? curl http://127.0.0.1:8000/api/health → {"ok":true}.
